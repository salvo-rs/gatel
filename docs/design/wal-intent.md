# 完整来源 WAL 意图载荷（内部实验格式）

`admin_wal_intent.rs` 实现纯内存编解码；没有文件追加、重放、结果决定或 HTTP 接口。
它不替换既有 GATELJ01 日志和 GATELC02 检查点，不能塞入旧文本事务的容量预算。
生产仍使用内存模式或显式 checkpoint-only 模式。本格式尚未作为稳定磁盘接口发布。

## 格式与校验

所有整数使用 little-endian；所有摘要为 32 字节，使用各自独立的哈希域。

| 偏移 | 字节数 | 内容 |
|---:|---:|---|
| 0 | 8 | GATELI01 |
| 8 | 32 | 后续整个正文的校验值 |
| 40 | 32 | 经现有实例绑定规则验证的实例摘要 |
| 72 | 32 | 宿主提供的构建指纹 |
| 104 | 32 | 请求身份摘要 |
| 136 | 32 | 原始前置 Version.etag() 的摘要 |
| 168 | 32 | 完整前置 Snapshot 编码的摘要 |
| 200 | 8 | 候选快照字节数 |
| 208 | 可变 | 完整 GATELS01 候选快照 |

单条载荷最多 16 MiB + 208 字节，内部快照继续遵循节点、深度、字符串和来源预算。
解码先检查总长度、格式和校验值，再核对实例、构建与完整前置快照；长度必须精确匹配，
内层快照不接受尾随字节。旧来源不能消失，修订不能为零或回退，同修订必须保持完整身份。
更高修订可以保存空 tombstone 或语义无效的配置：编解码不等于编译成功。

宿主必须在同一原子取样中取得 Version 与前置快照。编码只能检查修订向量一致，
不能证明调用者的取样过程。解码返回原始版本摘要，不将其当作新启动生命周期的 CAS 令牌，
也不自行认证它；未来重放层必须结合可信记录链校验前置关系。

## 请求身份与安全边界

客户端键为 1..128 字节可见 ASCII，大小写敏感，以已授权的 SourceId 为作用域进行哈希。
内部文件观察使用独立哈希域和新 BootId 生成身份。来源授权由宿主负责，身份不是授权凭据。
原始客户端键不写入元数据；Debug 和错误文字不包含键、配置、路径或任意诊断信息。
但键的哈希不是加密，完整快照可能包含密码和私钥引用等敏感信息，不能公开输出记录。
校验值用于发现损坏和上下文不匹配，不防止有写权限的恶意存储所有者重写记录。

载荷 identity 覆盖前置版本与完整候选快照，只表示这一笔具体意图的身份，不是持久化回执。
重试时不能先重新观察、分配修订再比较该身份，否则相同请求也可能变为不同意图。
未来入口需要先按作用域/请求键查询已保留的规范请求指纹，再决定复用原记录或返回冲突；
还需明确回执保留期、过期键语义、压缩后的索引迁移和恢复后的版本映射。

## 后续接入顺序

[二进制帧与决定载荷](wal-framing.md) 已有独立内存编解码和容量预留检查；以下完整接入仍待完成。

1. 定义有版本的二进制日志 framing、完整意图与决定记录的总容量预留；不能扩大旧文本常量冒充升级。
2. 实现单写者追加、同步、结果记录及不确定失败封锁，统一文件与 Admin 入口。
3. 实现受前置快照约束的重放、最后有效服务与最新拒绝意图恢复。
4. 实现规范请求指纹、持久化回执查询、重试去重与冲突语义。
5. 覆盖逐阶段 kill 恢复和压缩/轮转边界，再开放显式生产 WAL 模式。

当前五项单元测试覆盖往返/上下文、请求键、截断/损坏、重封校验值后的非法长度/尾随字节/
超大记录，以及重封后的零修订、回退和同修订复用；不构成上述持久化协议的验收。
