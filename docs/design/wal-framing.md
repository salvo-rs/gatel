# 二进制 WAL 帧与决定载荷（内部实验格式）

本模块接续 [完整来源意图](wal-intent.md)，仍是内存编解码，不进行磁盘追加、同步、
自动截尾、事务重放或生产请求提交。旧 GATELJ01 与 checkpoint-only 行为不变。

## 帧格式

| 偏移 | 字节数 | 内容 |
|---:|---:|---|
| 0 | 8 | GATELW01 |
| 8 | 8 | little-endian 非零、连续的记录顺序号 |
| 16 | 1 | 类型：1 意图，2 决定 |
| 17 | 7 | 保留字段，必须全零 |
| 24 | 8 | little-endian 载荷长度 |
| 32 | 32 | 载荷摘要，域 gatel.wal.frame-payload.v1 |
| 64 | 32 | 前 64 字节摘要，域 gatel.wal.frame-header.v1 |
| 96 | 可变 | 二进制载荷，不要求 UTF-8 |

意图载荷非空，最多为 GATELI01 上限；决定载荷固定 41 字节。
扫描本身只验证 framing，不解码 GATELI01 或判断决定语义；完整恢复必须继续通过上层校验。
扫描接收由可信检查点提供的 base 顺序号，不能从首条记录自行推断 base。
它返回最后完整顺序号、有效前缀长度和不完整尾部标记，不隐式修改输入或删除文件。
回调必须把状态暂存，后续任意记录失败时丢弃整次扫描结果，不能边扫描边发布服务。

完整头部先校验摘要，再读取长度，因此长度损坏不能把完整坏记录伪装成短写。
未写完的头部只能检查已有 magic 前缀，不声称能证明未知字节正确；需要显式恢复策略。
非零保留字段、未知类型、序号跳跃/重复/耗尽、非法长度和载荷损坏均拒绝。
摘要检测意外损坏，不提供对恶意存储写者的认证。

## 决定格式与容量

41 字节载荷依次为：8 字节意图顺序号、32 字节意图 identity、1 字节结果（1 Applied、2 Rejected）。
决定必须紧随其意图，不能指向零、自己、未来或更早记录；此协议不允许交错进行多个事务。
当前类型编解码验证长度、结果标签和相邻序号，未来重放层还必须核对 pending 状态与确切 identity。
Applied 是宿主作出的决定，不凭记录本身证明运行时已激活；Rejected 不能由等待者取消或未知 I/O 结果推断。
记录不包含任意错误文字，也不含 HTTP 回执或新启动后的 CAS 令牌。

扫描总输入上限 64 MiB；这是当前实验协议预算，不是可自动扩容的生产选项。
开始意图前 reserve_intent 同时预留 96 + 意图长度 + 137 字节，及两个顺序号。
算术使用 checked_add，恰好够用允许，超过一字节或顺序号不足拒绝。
这只防止软件容量上限阻止收尾，不能保证物理磁盘有空间或同步一定成功。

后续还需独立的 WAL 初始化/检查点锚定、独占追加存储、失败封锁、事务重放和回执索引；
不可直接复用旧文本日志存储打开此格式，也不能把新的帧测试当作 kill/断电恢复验收。
